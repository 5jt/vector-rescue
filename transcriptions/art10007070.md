by Robert Pullman
{ .byline }

The apportionment problem is to divide an integer n into m integer parts.

This problem occurs in several different sorts of business applications – financial planning, sales plan allocations, and top-down budgeting to name a few. Apportionment might only play a small role in the overall system, but it is likely to be used extensively in the system, and must work correctly.

This paper presents “Quick and Dirty” APL functions for apportionment. The functions are quick and dirty in that they provide a plausible solution regardless of the application.

Example 1: Straight-line calendarization.
A full-year budget of $n is to be evenly divided into 12 monthly amounts.

Solution:

```
    ∇ PORTIONS←SUM STRAIGHTLINE PARTS;APPROXIMATIONS;ROUNDERS
[1]   APPROXIMATIONS←PARTS⍴⌊SUM÷PARTS
[2]   ROUNDERS←(SUM-+/APPROXIMATIONS)DEALBITS PARTS
[3]   PORTIONS←APPROXIMATIONS+ROUNDERS
    ∇
```

Will it work? SUM and PARTS are assumed to be scalar integers, with PARTS>0. The claim is that:

```
SUM = +/PORTIONS
```

Informal proof:

By definition of floor:

```
(SUM÷PARTS) ≥ ⌊SUM÷PARTS
```

So multiplied by PARTS:

```
SUM  ≥ PARTS × ⌊SUM÷PARTS
```

Which is equivalent to:

```
SUM  ≥ +/APPROXIMATIONS
```

So:

```
(SUM-+/APPROXIMATIONS)?PARTS
```

Will work and produce rounders such that:

```
(+/ROUNDERS) = SUM-+/APPROXIMATIONS
```

So:

```
SUM = (+/ROUNDERS)++/APPROXIMATIONS
SUM = +/PORTIONS
```

So, with all due apologies for abuses of notation and rigor, we have shown that STRAIGHTLINE will work properly as long as its arguments suit our assumptions about them. So, of all the things that could go wrong with the development of a planning system, we could at least be sure that STRAIGHTLINE will not be among them.

Example 2: Top-down allocation

The company’s objective is to sell n units of a product at its five stores. It will allocate the units according to respective percentage shares of 10 20 27 20 23.

Solution:

```
    ∇ PORTIONS←SUM PERCENTAGE PROPORTIONS;APPROXIMATIONS;ROUNDERS
[1]   APPROXIMATIONS←⌊SUM×PROPORTIONS÷+/PROPORTIONS
[2]   ROUNDERS←(SUM-+/APPROXIMATIONS)DEALBITS⍴APPROXIMATIONS
[3]   PORTIONS←APPROXIMATIONS+ROUNDERS
    ∇
```

Will it work? SUM is again assumed to be a scalar integer, PROPORTIONS is assumed to be a vector of numbers, real or integer, with:

```
0≠+/PROPORTIONS
```

We again claim that:

```
SUM=+/PORTIONS
```

Informal proof: If:

```
0≠+/PROPORTIONS
```

then by combination of fractions:

```
1=+/PROPORTIONS÷+/PROPORTIONS
```

So we can equivalently write SUM as:

```
   SUM × 1
   SUM × +/PROPORTIONS÷+/PROPORTIONS
+/ SUM × +/PROPORTIONS÷+/PROPORTIONS
```

By the definition of floor:

```
(+/ SUM×PROPORTIONS÷+/PROPORTIONS) ≥ +/ ⌊ SUM×PROPORTIONS÷+/PROPORTIONS
                               SUM ≥ +/ APPROXIMATIONS
```

and the rest of the proof follows the same reasoning as Example 1.

There is one condition, not uncommon, that PERCENTAGE does not meet:
PORTIONS=0 wherever PROPORTIONS=0

This constraint can be taken care of by:

```
    ∇ PORTIONS←SUM NONZERO PROPORTIONS
[1]   PORTIONS←(PROPORTIONS≠0)\SUM PERCENTAGE(PROPORTIONS≠0)/PROPORTIONS
    ∇
```

Example 3: Calendarization of a top-down allocation.

The company has allocated n units in two different ways:

1. A full-year allocation to 5 stores.
2. A monthly calendarization of the company’s total plan.

It would like to construct a 5 x 12 matrix containing the calendarized plan for each store.

The row totals of the matrix must be identical to the full-year allocation to the stores, and the column totals of the matrix must be identical to the calendarization of the company’s total plan.

Solution:

```
    ∇ MATRIX←ROWS CROSS COLUMNS;I;BITS
[1]   BITS←ROWS≠0
[2]   ROWS←BITS/ROWS
[3]   MATRIX←((⍴ROWS),⍴COLUMNS)⍴0
[4]   I←1
[5]  LOOP:→LOOPEND IF I=⍴ROWS
[6]   MATRIX[I;]←ROWS[I]NONZERO COLUMNS
[7]   COLUMNS←COLUMNS-MATRIX[I;]
[8]   I←I+1
[9]   →LOOP
[10] LOOPEND:MATRIX[I;]←COLUMNS
[11]  MATRIX←BITS⍀MATRIX
    ∇
```

Will it work? ROWS and COLUMNS are assumed to be vectors of non-negative integers, with:

```
      0<+/ROWS
(+/ROWS)=+/COLUMNS
```

and we claim that:

```
ROWS≡+/MATRIX
COLUMNS≡+⌿MATRIX
```

Informal proof:

The only thing that could go wrong is that some iteration of line 7 leaves some element of COLUMNS negative. At each iteration of line 6 since:

```
ROWS[(⍴ROWS)]>0
```

we have the special case of:

```
ROWS[I] < +/COLUMNS
    SUM < +/PROPORTIONS
```

and so:

```
(PROPORTIONS[J]÷SUM) > PROPORTIONS[J]÷+/PROPORTIONS
    APROXIMATIONS[J] < PROPORTIONS[J]
             PORTIONS ≤ PROPORTIONS[J]
```

so no element of PORTIONS is greater than its respective PROPORTION, and so:

```
0 ∧.≤ COLUMNS-MATRIX[I;]
```
