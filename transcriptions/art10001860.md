*by Ray Cannon*
{ .byline }

This article contains the listing of all the Dyalog APL/W code needed to:

- Set the orientation of the default printer. (Global to all Windows applications) Function `SetGlobalOrientation`;
- Change the orientation within a single print job. (Local to the current printer) Function `SetLocalOrientation`;
- Examine the capabilities of the selected printer driver. Function `ShowDeviceMode`.

All of these tasks are performed by calls (via `⎕NA`) to Windows DLLs. The main function called is `ExtDeviceMode`. Calling Dynamic Link Libraries from Dyalog APL/W has been well documented in these pages in the past [1][2][3][4][5], so I will not go into much detail.

To standardize the interface between Windows and any printer attached, each printer manufacturer has to provide a piece of software (called a printer driver) which converts the Windows device-independent printer controls into the specific commands needed for their printer. Because capabilities of printers vary, a secondary task of the driver is to (on request) supply Windows with information about the capabilities of the printer. The structure used to pass this "control" data (as against "print" data, e.g. text or bitmap) between Windows and the driver is termed a `DeviceMode`. The function in the printer driver which utilises the DeviceMode is called `ExtDeviceMode`. At the Windows end, the information is used by the Device Context created for the printer.

A device context (DC) is a data structure created and maintained by the windows GUI in support of device-independent drawing operations on displays, printers, metafiles, and bitmaps. A DC is not only a toolbox containing a set of drawing tools, it’s also the permission slip to use a device and provides the connection over which "print" data (as against control data) is passed.

The Windows call to create a DC for a printer requires the DeviceMode supplied by the printer driver.

The three things `ExtDeviceMode` is called on to do in the APL function *SetGlobalOrientation* are:

1. Return the size of the DeviceMode structure required by the printer driver. This is then used to allocate memory for a DeviceMode structure.
2. Read DeviceMode information from the printer driver. The contents of DeviceMode are then modified as required to change the orientation.
3. Write DeviceMode to the printer driver. The printer is now set up for the amended orientation.

Since a change is made to the Printer Driver, the change can be "seen" by any and all applications using the driver. That is, the change is **Global to Windows**. Also Windows will remember the change even over a re-boot of the PC.

In *SetLocalOrientation*, steps 1 and 2 are the same, but in step 3 rather than writing the DeviceMode to the printer driver, it is used to replace the DC being used by the named printer object (via `ResetDC`). Thus the global environment is unchanged, but the orientation is changed for the named printer.

The function *ShowDeviceMode* displays the contents of the `DeviceMode` obtained from the printer driver. It shows which capabilities the printer driver supports (and which ones it does not).

For documentation on the (Windows) functions called, can I refer you to Microsoft’s Windows 3.1 System Developers Kit [6] (available from many sources in many guises, e.g. books, on CD, via Compuserve, on disc with language packages such as Visual Basic or Borland C++). The documentation I needed to get these functions working ran to over 20 A4 pages so cannot be reproduced within the limited pages of *Vector*. A copy of the workspace has been lodged in the APL section of the Portable Programming Library of Compuserve, and an earlier form of the WS is being distributed with the latest version of Dyalog APL/W (version 7.1).
