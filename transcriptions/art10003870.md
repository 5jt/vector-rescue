## Extension to Error Text

The name of the current verb (if any) is displayed along with the name of the error; having the current name makes it much easier to isolate errors in nested function calls.

**Example 0:**

```text
   mean=: sum % #

   mean i.9
|value error: sum                           the current verb is sum
|       mean i.9

   sum=: +/
   mean i.9
4

   mean 'asdf'
|domain error: sum
|       mean'asdf'

   (+/ % #) 'asdf'
|domain error                               the current verb is anonymous
|       (+/%#)'asdf'
```

**Example 1:**

```text
   mean=: 3 : '(sum y.) % # y.'

   mean i.9
|value error: sum
|   (     sum y.)%#y.

   sum=: 3 : '+/y.'

   mean i.9
4

   mean 'asdf'
|domain error: sum
|       +/y.
```

## Trace

The conjunction `13!:16` controls tracing.

```text
   u 13!:16 n
   (r,c) 13!:16 n
```

The right argument `n` specifies the maximum level of function call to be traced: `0` means no trace; `1` means immediate execution only; `_` means trace everything; etc. The left argument can be a verb to be used for displaying arrays in the trace (and is not itself traced during tracing). It may also be integers `r,c`, whence the system default display is used, clipped to `r` rows and `c` columns. (Two numbers suffice as clipping parameters because the output of an n-dimensional array is 2-dimensional on the screen.) Finally, it may be the empty vector, whence the current trace level and display controls are shown. The result is `i.0 0`.

The following sets of examples illustrate the use of the trace facility.

0. Controlling Trace
1. Tracing
2. Tacit Verbs
3. Explicit Verbs
4. Operators
5. Errors

## Example 0: Controlling Trace

```text
trace=: 13!:16
lr   =: 3 : '5!:5<''y.'''            linear display of an array

_ _ trace _       trace everything; display everything
9 trace 1         trace immediate execution only; display maximum of 9 rows
": trace n        same as _ _ trace n
lr trace n        linear display of trace output
```
