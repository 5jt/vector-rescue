*by R.G. Williams and R.G. Green*
{ .byline }

`⎕CT` is a system variable in APL which is applied when any two numbers are compared. Two numeric values are considered to be equal if their absolute difference is less than or equal to the value of `⎕CT` times the larger of the absolute values of the numbers being compared. Hence the applied tolerance varies with the magnitude of the numbers being compared.

For the majority of applications, this system is quite satisfactory, however anomalies can arise which cause a breakdown in the usual rules of mathematics. For example:

```apl
      A←÷1E16
      B←0
      ⎕CT←÷1E15

      A=B
0
      (1+A)=1+B
1
```

… which is contradictory to the assumption that if A, B, C are real numbers and A=B, then A+C = B+C.

The primitive functions affected by `⎕CT` are:

| | |
|---|---|
| `⌈` | *ceiling* |
| `⌊` | *floor* |
| `>` | *greater than* |
| `<` | *less than* |
| `≥` | *greater than or equal* |
| `≤` | *less than or equal* |
| `=` | *equal* |
| `≠` | *not equal* |
| `\|` | *residue* |
| `⌹` | *matrix inverse, matrix divide* |
| `⍳` | *index* |
| `∊` | *belonging to* |

… and in Dyalog APL:

| | |
|---|---|
| `~` | *excluding* |
| `∩` | *intersection* |
| `∪` | *union* |

When the equality of numbers to within an absolute tolerance is required, the following expression could be applied:

```apl
((÷⎕CT)×|A-B)≤1
```

This will overcome the previously mentioned difficulties.

This method is also suitable for comparing any number with zero as, the = primitive in APL will always return zero when comparing any non-zero value *A* with zero, irrespective of how close to zero *A* ever becomes.

This APL expression can be adapted easily to provide absolute comparisons with other aforementioned APL primitives.
