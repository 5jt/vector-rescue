## Overview

The utilities presented produce higher precision results than normal floating point. It is hoped that they, and their use to verify Knuth’s constants (Ref 1), are of interest.

The utility routines are applicable to other calculations requiring up to about 50 decimal places. Given further effort, the utilities could be presented as a high precision package.

## Practical Calculations with Rational Numbers

J provides rational arithmetic giving exact rational results. However, long calculations can lead to lengthy rational number representations which may require extensive storage and are slow to process. In these circumstances the theoretical infinite precision of rational numbers can be sacrificed by rounding values to an appropriate precision. In any case, any irrational values required, have to be rounded (approximated) in order to be held as finite length rational numbers.

For example, the repeated squaring of `pi` (an 80 decimal place approximation to the well known mathematical constant), shows that the length of the rational representation of the results just about doubles at each squaring:

```j
   0j5": drl *: ^: (i.5) pi
drl: 79 79
drl: 157 157
drl: 314 313
drl: 628 625
drl: 1256 1249
3.14159 9.86960 97.40909 9488.53102 90032220.84293
```

Where the `drl` utility displays the numerator and denominator lengths of the rational number results. Continued squaring would eventually fill the available memory or be so slow that one is not prepared to wait for the result. Even using the simple rational, 22r7, as an approximation to pi, creates rational values with thousands of digits after squaring 10 times.

The utilities presented round [intermediate] results to keep memory requirements and execution times within practical limits to achieve high, but not infinite, precision. The programmer and user then have the added responsibility of ensuring that the rounding is appropriate.

## The Utilities

### Maths Rational Utilities

The Maths utilities mimic similar built-in J functions, but with a restricted argument range:

- No complex arguments or results (applies to all the utility functions)
- Limitation of arguments to the range of J floating values (say ±1.6e308)
- Result values may be restricted to those near unity

| Name | Description | J built-in function mimicked | Algorithm Type | Approximate Arg. Limits at 45dp | Arg. Type x | y |
|---|---|---|---|---|---|---|
| `ca` | Cosine | monad `2&o.` | as sa | as sa | [N] | I, Q, X |
| `ea` | Exponential | monad `^` | Series | 70x | [N] | I, Q, X |
| `fa` | Factorial | monad `!` | Series | \_1< to <=6 | [N] | I, Q, X |
| `ge` | Euler’s constant, ( | (none) | Series | not applicable | [N] | I, Q, X |
| `pa` | Pi | `(o. 1)` | J `(o.)` | not applicable | [N] | I, Q, X |
| `la` | Natural logarithm | monad `^.` | Series | 10^300x | [N] | I, Q, X |
| `ra` | (Square) Root | monad `%:` | J `(%:)` | 10^80x | [N] | I, Q, X |
| `sa` | Sine | monad `1&o.` | Series | +/- pi\*10^3x | [N] | I, Q, X |

`pa` and `ra` make use of J built-in `o.` and `%:` monadic functions which produce extended integer results as a special case.

Argument types are: N any numeric; I integer; Q rational and X extended integer. In all cases the result is a rational value. Where the optional x argument is present, it is an integer specifying the number of decimal places of the result of the function (the default is the value in global variable `T`). The right argument may not be a floating or complex type numeric.

### Basic Rational Utilities

2. `l2r` enables rational numbers to be written as literal floating or decimal numbers

### Constants for the Rational Utilities

These are rational constants required by the utilities, but some may be useful to the J programmer directly. They are given to 80 decimal places including 5 guard digits.

| Name(s) | Description |
|---|---|
| `e1` | Base of natural logarithms, e |
| `ln2`, `ln10` | Natural logarithms of 2 10 |
| `lnu`, `lnx`, `lny`, `lnz` | Natural logarithms of 33r32 1025r1024 32769r32768 1048577r1048576 |
| `pi` | Pi |

The constants were produced using the J script itself, with the global control variable `ctr` set to zero. Thus, the script is not dependant on numerical values from any earlier work except in so far as such values are included within J itself.

## Calculation of Knuth’s Constants

### Run Constant Table script

The call `RCT KC` produces a listing of most of the constants in Table 1, Appendix 1 of Knuth’s book ( Ref 1). It might be expected that these could be extended to more and more decimal places. However, 50 decimal places is about the limit with the current utilities.

The 31 constants are calculated in about 5 seconds on an IBM compatible PC. The time is the time to run `RCT KC` on a system with an 233MHz Pentium II processor and 64 MB RAM. The time does not include the precalculated constants in the source file accessed by `RCT`, and their calculation times would need to be taken into account for an objective timing.

### Run Constant Table script Diagnostic

The `RCTD` function the displays number of common decimal places between pairs of results in order of increasing precision. It can be a useful diagnostic. A typical call is:

```j
RCTD KC    NB. Execution time 34 seconds
```

### Knuth’s Constants Table Data

The `KC` table contains three fields for each of Knuth’s constants (Ref 1):

1) Line No.; 2) Short description of constant; 3) J script to calculate the constant

The relation `(x^y) = ea y * la x` is used in 3) to calculate the power of a number in terms of the available rational utilities, `ea` and `la`.

Alternative J source has been used to calculate the constants in some cases. As an example, consider an alternative J script for pi:

```j
   0j45": *:fa _1r2
3.14159 26535 89793 23846 26433 83279 50288 41971 69133
```

When compared with Line 12 in the calculated constants, the difference is \_266e\_45 within the 5 guard digits, giving increased confidence in the utility results.

## The J Source

The J source code is provided ‘as is’, and consists of about 300 lines (4 A4 pages of J10pt).

If problems are encountered, a reduction in the number of decimal places will often enable a result to be obtained. This may be achieved by reducing the value in:

1. the global variable `T`, the default precision, or
2. the left arguments of a utility, where a utility precision is set explicitly
