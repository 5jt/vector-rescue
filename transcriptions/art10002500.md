*From: Eddie Clough, 29 March 1998*
{ .byline }

In his interesting article in *Vector* Vol.14 No.2, pp 121–124, Josef De Kerf notes that, so far, no algorithm has been found to calculate a given Niven number F(N) from N. I may of course be wrong but this seems to me to be a problem comparable with that of finding an algorithm to compute the Nth prime; i.e. there may little chance of eventual success.

A partial answer to the question of finding a faster algorithm may be to note the ease with which sums of digits can be found *en bloc*, so to speak, by repeated application of sum tables. Using J3 on a (Pentium 233) computer with 64MB RAM, I can find the digit sums for the first million integers in less than half a second. With these data, the Niven numbers can be identified in about 3 seconds. Beyond one million, the number of numbers being handled becomes so large that the swap file plays an increasing role, slowing the process down, leading to ‘out of memory’ for `10^8` integers. However, the Niven numbers in the second, third, etc. million can be found equally quickly by adding 1, 2, etc. (or their digit sums) to the digit sums found for the first million. In this way the Niven numbers less than `10^12` can be investigated. There are in fact 27975 Niven numbers in the millionth group of millions of integers, the largest being 999999999903. (I can’t tell you which position it occupies in the complete Niven sequence.)

In the following realisation, the J verb, `niv`, may be used monadically to produce the digit sums for `10^y` integers (including zero) and then dyadically to find the Niven numbers among the `x*10^(y)` to `(x+1)*10^y-1` integers, where `x` and `y` are respectively left and right arguments of the verb. If `y` is set to 6, the integers are explored in groups of one million. If ‘n’ successive millions are analysed by one J statement, the verb reports, for each successive group, the total number of integers examined up to that point, the number of Nivens in the group, the Nivens in the group (recorded for later interrogation in a vector `FN` but overwritten by the Nivens in the next group, if there is one), and the total number of (overwritten) Nivens in the previous groups, this last being given to enable an ‘`N`’ to be associated with each finally recorded ‘`FN`’. The example provided shows the analysis of 10 successive groups each of `10^6` integers; analysis time is proportional to the number of groups and this analysis took 30 seconds. (If a smaller group size is used, e.g. `10^5` integers, the time per group falls so that there is very little difference in the overall time to examine the same total number of integers — but the number of Nivens stored for interrogation falls.)

[In another article, *Vector* Vol.14 No.3, pp 138–142, De Kerf looks at Armstrong numbers. The above approach can be adapted to study this domain. The analysis is quite straightforward as far as the first group of integers is concerned, but beyond that matters become slightly more complex. For example, if the sums of 8th powers of the digits of the six-figure integers up to `10^6` were found, they could only be used as a basis for finding the Armstrong numbers in the 10th to the 99th million groups, i.e. for the addition of two and only two digits.]
