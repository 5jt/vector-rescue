## Magic

The instructions for this game are provided as an option in the function. A randomly selected matrix of 0s and 1s is presented, and the player is asked to select from a standard set of matrices (also 0s or 1s). The selected matrix is used to complement some of the values in the original matrix. The aim is to get a matrix of 1s with a lone 0 in the centre.

The instructions are printed after the function for convenience.

## OXO (Noughts and Crosses)

Mr McLean’s second game is already designed to be played against the computer. The positions on the noughts-and-crosses board are labelled:

```
1 2 3
4 5 6
7 8 9
```

The player (human) plays `X` and the computer plays `O`. You are offered the choice to play first or second, and the board is displayed after each move.

The variable `REFTABLE` contains all the possible winning positions:

```
1 2 3
4 5 6
7 8 9
1 4 7
2 5 8
3 6 9
1 5 9
3 5 7
```

This is used to index other arrays. The `BOTH` array fills up with 1s (for the human i.e. `X`) or 10s (for the computer i.e. `O`)

The algorithm used by the computer is simple. It first checks whether it can win (a row in `8 3 ⍴BOTH[REFTABLE]` which adds up to 20). If a computer win is not possible, it checks for a human win (a row adding up to 2) and blocks if necessary. Otherwise the computer prefers to play the centre (if it gets the chance), a random empty corner, or just any square available.

The computer does not always win. Any offers of a better algorithm?
