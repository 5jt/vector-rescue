A Survey of ⎕NC

Vector 7:1, page 127

language design implementations standards

Transcribed from the printed issue; not yet reviewed. Read it in the PDF of the issue, page 127

by Joseph L.F. De Kerf

Abstract¶

Originally the user of APL could only identify the types of the objects in his workspace with the system commands )VARS, )FNS, and - if groups are supported - the system command )GRPS. In addition, in most implementations the listing displayed cannot be trapped in the form of an explicit result. To overcome these deficiencies, the system functions Name Class ⎕NC and Name List ⎕NL have been incorporated. A survey is given of the related name class implementations for about forty APL dialects. Remarks concerning the standardization of this name classification are stated.

Name Classifications in APL¶

APL does not need explicit data typing. Variables are introduced by the user through assignment and their type and structure may be changed dynamically. User-defined functions and - if supported - user-defined operators are introduced either with the editor or in some implementations through direct definition. If supported, variables and user-defined functions/operators may be collected to groups. As such, the user is building up a set of reserved words - the names of the objects in his workspace. Eventually, the user may discard members of this set by erasing or expunging.

Originally the user could only identify the types of the objects in his workspace with the inquiry commands )VARS for a variables listing, )FNS for a defined function listing, and eventually )GRPS for a group listing. More recently, the system command )OPS has been added for - if supported - the defined operator listing and the command )NMS for the listing of the total set of object names. Each of these commands displays the names of the objects in alphabetical order, eventually restricted to an alphabetical subset as specified by the parameter(s) of the command. In most implementations however, the listing displayed cannot be trapped in the form of an explicit result.

To overcome the deficiencies of this approach, the system functions Name Class ⎕NC and Name List ⎕NL were incorporated. ⎕NC returns as explicit result a vector of name class integers giving the local usage of the identifier in the corresponding row of the right argument matrix. ⎕NL returns as explicit result an array containing the name list of the local identifiers specified by the right argument scalar/vector of name classes. In its dyadic form, the name list is restricted to those identifiers whose initial character is the same as one of the characters occurring in the left argument character scalar/vector. Whether the names are listed in alphabetical order or not, depends on the implementation. In most implementations the names are alphabetically ordered, but in some implementations the names are listed in fortuitous order or in the order as they first appeared in the workspace.

Note: For those implementations which support the system command )NMS, the names listed by this command are followed by a dot and their name class. The name classes are the same as those produced by the system function ⎕NC.

Name Class Implementations¶

Descriptions of name class implementations for about forty dialects are given at the end of this paper. For purposes of comparison the list starts with the standardizations proposed A.D. Falkoff and D.L. Orth at APL79 (1979) [1] and by the ISO Draft International Standard DIS 8485 (1986) [2].

The descriptions give the name classes returned by ⎕NC. Any deviations of those used by ⎕NL and additional information if significant are reported in the form of a note. In most implementations ⎕NC returns name class 0 for names available without active referent, name class 1 for line labels, name class 2 for user-defined variables, and name class 3 for user-defined functions.

In many implementations ⎕NC returns name class 4 for names not available: invalid names, distinguished names, and - if supported - group names. In some implementations however, name class 4 is reserved for groups only and in all implementations which support user-defined operators name class 4 is reserved for such operators. Invalid names in those implementations return an individual name class such as ¯1 or cause an error report such as "domain error" or "name error". Names of system variables and system functions in those implementations return an individual name class such as 5 and 6 respectively or are treated as common objects by ⎕NC but are not listed by ⎕NL. In VAX APL Versions 2 and 3, a distinct name class is associated to niladic and non-niladic system functions. Maybe this is done because niladic system functions are in fact system variables, shared between the workspace and the processor, but which are reset by the processor before they are used.

⎕NC returns the name classes for the local usage of the identifiers and ⎕NL lists the local identifiers of the type(s) selected. In some implementations additional facilities are provided for identifying global usage or/and for listing the global identifiers:

  • In Xerox APL (Atkins), classification codes returned by ⎕NC and used by ⎕NL are different. Name classes 2/3 list the active variables and functions, while name classes 5/6 list the global variables and functions. 3 ⎕WM 'type' corresponds to ⎕NL, 6 ⎕WM 'namelist' corresponds to ⎕NC, but 7 ⎕WM 'namelist' identifies the global use instead of the local use of the names listed.
  • In APL 2.0 and NOS/VE APL (CDC), the system variable ⎕ENV controls whether ⎕NC and ⎕NL refer to the global or the current environment. When 0, the global environment is used. When 1, the current environment is used. The default is 1. When the state indicator is empty, the global and current environment are the same and ⎕ENV has no effect.
  • In OS4000 APL (GEC), ⎕NL may list global objects: name classes 2/3/4 are used to list local variables/functions/groups, while name classes 5/6/7 are used to list global variables/functions/groups.
  • In 2900 APL (ICL), ⎕NC may be used dyadically. If the left argument is 0, global classifications are reported. If 1, current classifications are reported. The default is 1. If the left argument of ⎕NL is 0 instead of a character scalar/vector global objects are listed. If 1, current objects are listed. The default value is 1.
  • In SHARP APL (IPSA), 1 ⎕WS versus ⎕NL and 5 ⎕WS versus ⎕NC provide similar information but classification codes are different. In addition, 5 ⎕WS reports the name class at each level of the state indicator, the global definitions included.
  • In APL*PLUS (STSC), ⎕IDLIST versus ⎕NL and ⎕IDLOC versus ⎕NC provide similar capabilities, but classification codes are different. In addition, ⎕IDLOC reports the name class at each level of the state indicator, the global definitions included.

Note: Some implementations reserve separate name classes for non-standard objects, such as intrinsic functions in Xerox APL (Atkins), special functions in NOS/VE APL (CDC), APLGOL functions in APL/3000 (HP), and special data types in MCM/APL (MCM). More details may be found in the descriptions given below.

Name Class Standardizations¶

In the standard proposed by A.D. Falkoff and D.L. Orth at APL79 (1979) [1], unavailable names return name class 4. In ISO DIS 8485 (1986) [2] however, such unavailable names cause a "domain error". This permits the implementor to add name classes as consistent extensions.

In the meantime, ISO-IEC/JTC1/SC22/WG3 is preparing a new standard for Extended APL. As this new standard will probably support user-defined operators, it is obvious to associate name class 4 with those user-defined operators. At the same time it would be opportune to introduce extra name classes for system variables and system functions, for instance name classes 5 and 6 respectively. This would give the user the opportunity to list the system variables and system functions available in his processor. the complete set of name classes would become:
0 for identifiers available without current referent
1 for labels
2 for variables or shared variables
3 for user-defined functions
4 for user-defined operators
5 for system variables
6 for system functions

Finally, a mechanism should be standardized to give the user the possibility to choose whether ⎕NC and ⎕NL refer to global or local objects. The most handsome method seems to be to make available a system variable which controls this choice, such as is done in APL 2.0 and NOS/VE APL (CDC) with the implementation of the system variable ⎕ENV.
