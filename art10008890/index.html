Watchpoints in APL+Win 3.6

some experiments by Adrian Smith

Background Those of you who build applications in Causeway (shareware will know that its main design objective was to take away from the programmer (me) the responsibility of remembering which Gui objects needed to be updated when some underlying data changed. Now I think it is fair to have the programmer state explicitly the dependencies (“this field will need fixing when any following change ...”) although the screen design software can usually make a fair guess just by stripping the valid names out of the object’s data expression; what is not fair is to have to remember to notify  the change to some variable when you run a callback that re-assigns it. Surely the interpreter knows that you assigned some new data to user_name can’t it just tell the program?

Where do Watchpoints come into it? The concept of watchpoints has been around in real  development environments for years, and several old mainframe APLs (Xerox, Burroughs?) had something similar. Dyalog actually demonstrated ) watch in an early version of Dyalog/386 at a BAA meeting (to general acclaim) but somehow it never made it Windows interpreter. J has a related idea in the 4!:5 conjunction which reports all the names which changed since you last called it. For debugging, watchpoints are just amazingly useful. For example in my Rain graphics engine, I build the description of the chart as a simple character vector of PostScript code. This involves a lot of APL like ...

R+R,‘C ',(CHSFMT XPOS,TLF,XPOS,YL),' ] ',ATT,' ps pL ',nl

... to draw a polyline (1 think this may be a Y-axis). Quite often, my fingers get ahead of my brain and I forget to format the co-ordinates. APL is horribly tolerant of this kind of misdemeanour, so everything carries on until I hit WS FULL (because I now have some horrid nested heterogeneous miscegenation lurking in my workspace) or until I try to view the chart, save it to file etc.

Now at the end of each block of code, the temporary variable R gets catenated toa global buffer with an expression like:

CHAPG+CHAPG, ps

.. Just suppose we could watch  this buffer and pull up short the moment it ceased to be a pure character vector? Well now we can, and it is amazingly easy to set it up:

Qwatchpoints+1 2p'CHAPG' ~a/CHaPGelav' chPlot 112 WATCH POINT TRIGGERED ~a/CHaPGeDav A si DwArcHPOrINT[i} CHacatle] chPlot{22]

So what happened, and where am I? Every time 1 make an assignment to the buffer, the expression ~,/CHAPGe(av is evaluated. If it is true (non-zero) then my code is immediately suspended in a phantom function called QWATCHPOINT, and I can look at the stack to see which line of my code caused the problem. Note that the help misleading here - it states The first column holds the name of the variable whose imminent change in value will trigger evaluation of the expression in the second colunin; ...” which implies that the suspension will occur before the damage is done. In fact it does the assignment first, but at least you have the smoking gun to hand.

Now, you can call functions in that right-hand column (whinge #2 ~ the help file states If the function returns a zero or no result, execution will not be suspended, but whatever code the function contains will have been executed.” but in fact you must return a result) and you can run as many expressions as you like against the same variable ...

Qwatchpoints+3 zp'x' 'QO+''x has changed'' x! X*12 x has changed 12 X has changed 12 x has changed 12

... but you can abuse it with things like ....

Owatchpoints+i 2p'x' 'Ok''x has changed'' (x+x+i)?

While we are in the mood, whinge#3 - the help file is quite explicitly wrong in stating Note also that the single character variable name Z must be raveled to a vector before assignment; scalars are not accepted.” - scalars are accepted, the example on the previous page.

This all begins to feel rather useful, not just as a debugging tool but quite possibly of a real application. Suppose we are running a +Win OLE server using Excel as the Gui interface. Maybe this is running some fancy statistical model, and it might maintain some intermediate variables to show how it is getting on. Perhaps the spreadsheet could display these variables as they change? Now all we have to do is to watch  the variables in our server and use the Notify method on root to tell Excel that something changed, and probably what it is and the new value.
