BAA-GUI: APLs and The Windows GUI Dyalog APL Sessions notes by Jonathan Barman

The Dyalog APL stream for the GU] Programming day was split into two groups. Peter Donnelly of Dyadic Systems Ltd. took one group while Adrian Smith, wearing his APL-385 hat, took the other. At lunch-time the groups swapped over. I attended Peter's tutorial in the morning and Adrian's in the afternoon, so I have described the tutorials in that order.

Peter Donnelly Peter took us through the basic GUIfacilities in Dyalog APL. It would be too muchto reproduceit all here, but the following fragmentof his introduction will give you the flavour of the way in which he started very simply and then gradually introduced more complex examples:

'pete'Qwe'form! 'pete'Qwe'form' 'Hello World! pete'Dwe'form' Hello World'(10 30) (10 10)

Thefirst line creates a blank form with everythingleft as a default. The next line tedefines the windowwith title. The third line redefines it again with title, position and size. Peter continued this process with more and more examples until he had covered all of the 0 functions OWC OWG OWS OWN and DQ. The coverage was quite thorough and included howto create buttons, radio buttons, list boxes, groupsetc. etc. We were shown howto run callback functions which can be sparked off when usercarries out a particular eventsuchasclicking on a buttonorselecting a control.

I attemptedto type in the examples as Peter ran through them. I must admitthat I had sometrouble keeping up as Peteris quite a fast typist. Several peoplein the class also had trouble, so they wisely sat and watched carefully rather than try and reproduce everything at the terminal. Fortunately Peter s examples were almost the same as those in WINTRO, which is the introductory Windows workspace supplied with Dyalog APL, so one could always work through them at a more leisurely pace on one s own. In retrospect, I think that it would have been wiser to have got everyone to run the WINTRO workspace whereall one hasto do is to press the F1 key to get the exampletext. If you have Dyalog APL,

Adrian Smith Adrian started off by giving us an overview of three things:

+ what we wouldgetoutofthe session

+ what Adriangets outofit

+ the design philosophy behind his GUI workspace

What wegot wasan excellent GUI design workspace with open code so that we can all do the usual APLthings of tweaking the bits we don tlike to turn it into a tool that really sings. What Adrian got out of it was feedback on his design, which will hopefully continue. This includes reports of any bugs in his workspace, which is a beta-test version, and comments or suggestions for improvements in the facilities available. Adrian also wants everyoneto have fun developing GUI systems, which should increase the use of APL generally.

The design philosophy behind the GUI workspace is sort of object oriented. Adrian did not want to use the word object becauseof all the connotations with Object Oriented Programming. The way in which he has got messages passing to windows when an APL variable changes does makeit feel a bit object-ish, thoughit obviously is not OOP.

I included in my review of Dyalog APL 6.3 (see Vector 10.1, July 1993, page 66) the initial version of the workspace, and was impressed then. This version is a great improvement. Adrian gave us the briefest of introductions on how the thing worked, and everyone seemedto beable to get going really fast creating GUI objects and getting quite complex things to work. 1 would have preferred a little more introduction to the features available, but that was probably becauseI had seen a prototype and immediately tried to do sometricky things where I had had somedifficulty.

Conclusion I felt that the Workshop wasa great success. Everyone had a PC to themselves so there was no problem in getting down and solving one s own problems. There were not too many people in each class so the tutors could give individual attention where necessary. The course material clearly set out the way in which GUI systems could and should be built. And, as an extra bonus, we all carried home disks filled with useful code. I would certainly attend similar tutorials which maybe held in the future.

Whatthe Presenter got outof it! by Adrian Smith This was the best usability lab 1 could have wished for. I was generally delighted with the ergonomics of the designer, but picked up an obvious need for caption , position , style to be grouped into a single Appearance dialogue .. done! Less obvious was the need for local variables at the form level. This makes it very mucheasier to leave thingsstrictly alone until OK is hit (mostly done). Some objects need to be more forgiving (fewer LENGTH ERRORS when your boolean doesn t match youroptions!), and also morecatholic in their tastes (nested vectors or simple rank-2 arraysin list boxes).

Anyone whodidn t get a copy, and could usefully play with this stuff, please send a disk to APL9385 with a return address and appropriate postage. Just don t build a real system yet the design is stabilising, but I don t wanta user- basejust yet.
