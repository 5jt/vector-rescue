Hackers Corner: Hack My Exe by Michael Baas (ntichael@mbaas.de)

Introduction Dyalog s V10-feature to compile a DWS into an EXEisreally useful, as EXEsare easier to share withothers (not requiring shortcuts to the runtimeetc.). Evenifit was possible before to share programs,it is just more fun now to write small utilities and have them available as EXE. (Now if only the accompanying DLL could be smaller - but that s anotherissue). The only issue I had with Dyalog s EXEs wasthat Dyalog did not give me control over the program- andversion- information which showsupin the file-properties. So I started to research ways of changingthat information. This article describes myfindings.

Whenfirst hearing that V10.1 would include a possibility to controlthese,I thoughtthis article would be redundant,butit isn t, as you get additional benefit from features not (yet?) available in Dyalog stools: the tools described here allow for a fully automated build-process, so all properties can be set under program- control, andit is also possible to put additional resources into the EXE, like, for example, additional icons, so that your users have a choice.

Ingredients Dyalog s EXEsare created in the Win32 PE-Format. PE stands for Portable Executable and is the standard-format for programsin the Win32-World {actually also for Win64, although with some modifications). More about the format can be found on the web, one comprehensivearticleis [1]. The important pointis that since this is a standardized format, we can use anytoolto edit those structures, there is no hidden APL-magic preventingthat.

There are various tools available on the internet to edit EXE-files, one tool that provedvery suitable for the job was Resource Hacker[2] which has the advantage of being available as freeware.

With Resource Hackerit is possible to edit the version-information in thefile and add icons to it - interactively. The program also has a command-line mode and supports scripting, but in that modeit requires pre-compiled resourcefiles which it then inserts into the EXE.

Compiling - again So, to automate the whole process,it is necessary to create a resource-file (. RC), compile it with a resource-compiler, then use Resource Hacker to update the resource-info in the EXE with the compiled . RES-file.

Fortunately thatall is not as difficult as it may sound. A resource-compileris included with Visual Studio (Common\Tools\Bin\RC. EXE) andif you don t have VS, you can download GoRC. EXE forfree [3]. | had an issue when using GoRCto compile the resources,as finally the EXE wasstill showingthe old version-info, yet I had noerrors in the whole process. It finally turned out that the initial RC (created by using ResourceHacker s info) had no language-information in itand so GoRC used Windows regional settings to determine a default- language (which, in my case, was wrong: I used German windows, but needed English language-info). Surprisingly Microsoft's RC did not have theseissues,asit seemsto use a hardcoded default ENGLISH,ENGLISH_US which wasexactly right in this case. Anyway, the moral of the wholestory: correct (English) language-info needs to be included in the .RC
