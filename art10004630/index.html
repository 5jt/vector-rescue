APL "RISC" Programming Style by G. A. Langlet

In general, APL functions listed as examples in books or tutorials can be improved in many ways. Let us take as an example the nice COUNTALL function presented by Alan Sykes in Vector Vol.5 No.3 page 31. This well known algorithm returns the frequency table of vector X with unique values in ascending order within the first column.

VR*COUNTALL X;I;N [1] X*XE4K] 6 Rel 2 p( 14K), px {2] +(X[1J=x0px])/0 [3} I#(10X)#X $9 NeI/ipr [4] R#(I/X),[1.5]N-0,~14N v

It works perfectly except when X is not a vector (RANK ERROR), O10 is set to 0 (INDEX ERROR), or X is an empty vector (INDEX ERROR), Let us now introduce the following version.

YR¢COUNTALLV X C1] X#,X 9 ReT1+14K¢XL AX] 9 REK#1PXER,K © Xe14R/K 4 R+X, [[1IO+.5]14R-" 1OR+R/ PR Vv

ONSIZE'COUNTALL* 272 (SIZE OF OBJECT IN APL*PLUS/PC) ONSIZE'COUNTALLV' 192 (I.E. 405 LESS)

COUNTALLV runs correctly for any numeric array in either origin. Both functions still produce DOMAIN ERROR when contains characters; people would probably prefer to take another algorithm for counting words in a text anyway. Benchmarks have shown that both functions consume the same CPU time in various situations, e.g. about 2 seconds on an 8MHz PC-ATfor 100=pXx.

Why use goto, locals and, most of all parentheses when their use is absolutely unnecessary, even for didactic purposes?

I have written thousands of functions in APL.68000, Dyalog, APL90, Sharp and APL*PLUSwithout labels, branches, parentheses (except for SS in APL.68000)- and of course without any diamond in APL2 and I-APL. Moreover, the use of matrices or higher arrays is to be avoided when possible. So many nice algorithms can be developed with

vectors! Matrices are nice for output only ... when the specification requires them. One can also almost completely discard execute and also encode, decode, transpose, outer product, +7, +4, and catenate on large objects. The use of trigonometric functions and of the domino can be drastically reduced in graphics with a minimum of thinking. The each operator will also remain a monsteras long as APLinterpreters or compilers do not really optimiseits effects.

The "RISC"style will consist in using:

a) Simple andfast primitives, most of the time on vectorsonly.

b) Structured programming sothat any function will alwaysbe executed from the first to the last line.

e) Short modules: no unlocked function should exceed one screen in size.

leven strongly discourage people from buying or reading books in which branches are a strong topic. In all cases, functions provided in courses should take careof the 010 effects, and give no errors or yield explicit messages when arguments are empty or have the wrong rank; they should respect the ISO standard, be executable in several implementations without pernicious side effects and continue to work when the workspace is almost full; the use of locals, parentheses or long lines often eats space unnecessarily. People should teach how to build APL applications from small bug-free modules and howto avoid the traps.

Start Building your own Utilities by Peter Branson

Whatare Utilities?

As you get going with APL, you mayfind it useful to start building up library ofutility functions. These are functions not tied to any particular APL application, but come in usefulall over the place, such as alphabetical sorting, selecting a particular name froma list of names. It may be that your APL has the nucleus of a good set in a supplied workspace. Use them. The oddsarethat, sooner or later, you will want some of your own. In any case writing utility functions helps extend one's knowledge of APL, since some care is needed to make them robust.

A Useful Example

Let's look at an example. When handling character (text) data, there is often a need to join two matricesof characters one abovethe other - the technical term is catenation on the first axis. The direct APL wayofdoingthisis:-

(3 3p'CATANDDOG') ,{1] 2 3e'XYZ* CAT AND DOG XYZ RYZ

Here the bracket index join , [1] tells APL that we wantto join the right argument onto the bottom ofthe left argument. Note that the example above will only work when the two matrices have the same width.If they are not the same you will get a length error (try it and see).

Now, whatif the matrices do have different widths, which occursfairly often? A simple line of APL will no longer suffice, so let's set up a utility function for this. I will call this VCAT with a header R<A VCAT 8. Here A and B maywell both be matrices, but it would be usefulif the function would work with vectorsas well.

For example, we might sometimes wantto add just one nameto a namelist, in which case B could be a vector. And while weare atit let's allow for the case where A or Bisa singleton; a one-elementvectoror even a scalar.

How shall we do this generalisation? Well, yourfirst thought might be to do sometests on the shape of A and B and, according to what type of object each is, to branch to different parts of the function to do whatis needed. But this is APL, remember, andof course there is a better way, without branches! Hereis one wayof writing the VCAT function:

Vv RtA VCAT B;MAXW;TOP;BOT [1] a VCAT: VERTICAL CATENATION [2] a EXTEND SINGLES AS REQD. FOR MATRIX RESULT - NUM OR CHAR [3] aA {4] A<(~24 1 1,pA)pA £5] Be("2t 1 1,9B)pB [6] MAXW+(~1tpA)[~1tpB [7] TOP+((1tpA),MAXW)tA £8] BOT<((1+PB) ,MAXW) +B [9] R+TOP,{[1] BOT v

Havea look at line 4; this finds the shape of A (the result of shape is always a numeric vector), catenates this onto the vector 1 1 and uses the last two elementsof the result to reshapeA. If Ais a two-dimensionalarray to start with, it will be unaffected; the reshape will be to its original shape. If it is a vector it will be reshaped to a one-row matrix of the original vector length andif it is a sealar (the shape of a scalar is the empty vector) then it will be reshaped to a one-row, one-column matrix.

The next line does the same for 8, and line 6 just gets the larger of the two widths. One of lines 7 and 8 will always be redundant; if either of A and 8 has fewer columns than the other then a take (+) with the MAXW number of columnswill pad it with blanks if the argumentsare characters and with zerosif the arguments are numeric. This capability of take is often called overtake , a term worth rememberingif it helps to fix this in your memory. And as you will have realised vCAT has the added bonus that it works for numeric data as well as characters.

A Documentation Utility

Looking back at VCAT you will see that the first line is a comment showing the function namewith a brief description of what it does. Many experienced APLers put comments like this in all their functions, so that by running a suitable documentationutility, a list of names and outline descriptions can be obtained for all the functions in the workspace. This can be useful as the number offunctions builds up; it is only too easy to forget what some of them do, and their names(often kept short for typing convenience) may not be mnemonic enough so )FNS won't do the job.

Comment or Decomment

Experienced APLers often recommend that all functions be extensively commented, either to explain some ofthe tricky APL or to hélp describe the overall task. There are times when you may want to remove the commentse.g. if space is short.

You could )SAVE the workspace under a different name and then run DECOMMand )SAVE with the usual name. Don't fail to keep a commented copy.

Vv R*DECOMM FNAME ;CR3MASK {1] a DECOMM: DECOMMENT A FUNCTION £2] CR+OCR FNAME [3] MASK+CR[;1]#'a £4] CR<MASK/CR [5] R¢OFX CR v

Here we form CR as before and then do a not-equals comparisonof the first column with the lamp symbol. This gives us a boolean vector with ones for the lines we want to keep and zeros for the lines whose first characters are lamp. Then we compress CR to remove the unwanted lines and finally convert CR back to a function with OFX. As it has the same nameit will overwrite the previous version.

One disadvantage of DECOM! is that it will remove the first line comment. The simplest modification will keep it: add line:

[3.5] MASK*MASKY(pMASK)#0 1

This ensures that line one is always represented by a 1 in MASK.
