Emulating APL*PLUS/PC Native Files by Adrian Smith

Background I never took any great delight from coding for the old O¥READ functions in APL*PLUS/PC, but at least they were fast and totally reliable. [ can also appreciate that there is a lot of application code out there which would really appreciate a no-brainer conversion to Dyalog/W. This particular collection of functions sets out to emulate the old native file standard quite closely (even failing on DOMAIN ERRORSattheright places) so please let me know where you find inconsistencies.

Howit all works The basic technique is to overload the various OWA calls so that the same code can be used to read characters or mumbers(integer / float) without the overhead of data-conversion in APL The speed on integers is quite frightening ~ this will read 4000 integers from a random offset into a 4Mbyte datafile in less time than you can measure.

Just for the funofit, I have also included a cover for 0FREAD to pull in data from an APL*PLUS/PC componentfile. If anyoneis up to the challenge of completing the set of these (and extending the set to cover PLUS I files) pleasefeelfree.

Limitations It is not obvious to me what happens to a componentfile with more than 128 components! The PLUS/PC strategy is to allocate space on the index for 64 components whenthefile is created. When you write the 65th, it clears space for another 64 (re-locating anything that was in the way to the end) and so on. The above FRead function will cope quite nicely, but I cannot see an easy way for FSize to know howfar to look into thefile for the one beyond the last marker of 4 consecutive zeros! To save searching the entire file redundantly, I just give up at 128.

Ps Apologies to non-Dyalog users for the gratuitous use of slash-commuute-gets in several of the functions above. I gota little carried away, but I am better now.
